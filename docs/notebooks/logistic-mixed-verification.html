Binomial mixed-model verification and approximation accuracy

We compare the native binomial random-intercept fitter with R lme4, and independently evaluate its likelihood with SciPy. The model uses marginal maximum likelihood, a logit link and a Gaussian random intercept. Inputs remain plain design/outcome/group arrays. See the math walkthrough and contract.

Seven input datasets are fitted with 1, 9, 25 and 61 nodes: 28 comparisons. They cover binary outcomes, grouped counts with offsets, no fixed intercept, small/unbalanced groups with rare events, large group variation, a zero random variance boundary, and the published cbpp model. R references use BOBYQA with rhoend=1e-9 and tolPwrss=1e-12. Codes must be zero and saved warnings empty. Rust/PHP tests compare every coefficient, covariance/inference value, observation prediction/residual, conditional group mode, scale, normalized likelihood and AIC/BIC.

The independent Python evaluator uses Brent root finding for conditional modes, NumPy Hermite nodes for the same approximation, and QUADPACK adaptive integration for a separate numerical accuracy check. Its matched-approximation likelihood must agree with native output within 2e-8 absolute. QUADPACK error estimates are recorded; they are numerical estimates, not mathematical error guarantees.

The independent SciPy optimizer starts from a statsmodels binomial GLM and SD=1, not from native mixed estimates. It optimizes the numerically integrated cbpp likelihood and checks its estimates against high-node native output.

statsmodels BinomialBayesMixedGLM uses Bayesian posterior estimation with priors on fixed effects and variance parameters. That is a different objective, so we do not claim equivalent mixed ML estimates from it. statsmodels GLM verifies the exact zero-random-variance reduction instead. The full mixed-model Python reference here is explicitly SciPy.

For grouped-binomial responses, lme4 nAGQ>1 computes its reported criterion using conditional deviance relative to the saturated model. Its additive constant differs from nAGQ=1. We retain the raw R value and restore the saturated log likelihood, sum(dbinom(successes, trials, successes/trials, log=TRUE)), before comparing normalized likelihoods and AIC/BIC. For binary observations this constant is zero. This convention is disclosed in the glmer documentation.

The native likelihood always includes binomial coefficients and Gaussian normalization. Changing node counts does not change its additive convention.

The likelihood errors are measured at each approximation’s own fitted parameter vector, using independent integration. They are not differences between log likelihoods at different parameters. The rare-event fixture makes the distinction visible: Laplace agrees with R but substantially changes estimated group variance. Higher node counts improve this example; 61 nodes is still an approximation. Check estimate sensitivity to node counts when groups are small or events rare.

Numerical tolerance and failure policy

  • Estimates/predictions/group modes: absolute 2e-5 plus relative 2e-4.
  • Covariance, standard errors, z tests, p-values and intervals: absolute 2e-5 plus relative 2e-3; R and native use independently computed finite-difference Hessians.
  • Likelihood/AIC/BIC: absolute 1e-6 plus relative 1e-8.
  • Independent matched-approximation likelihood: absolute 2e-8.
  • Sample metadata, group ordering, integer counts and singular flags are exact where checked. Boundary reduction also checks equality with the native GLM.

The coefficient covariance is the fixed block of inverse joint marginal observed information, including scale coupling. A nonpositive Hessian, excessive final score, invalid/aliased design, fixed separation, invalid counts or exhausted budget throws an error. Controls have explicit parameter bounds; convergence is local and does not prove global optimality. Missingness follows the existing listwise policy with one warning and original retained/dropped positions.
