Gaussian mixed models on four published datasets

We verify the optimized random-intercept ML implementation on four published datasets, in addition to the synthetic fixtures, closed-form variance test and million-row benchmarks. Every model uses the same explicit fixed columns and observations in R lme4, R nlme, Python statsmodels and PHP. Data provenance, original research references, CSV downloads and checksums are in the data-source record.

These are numerical comparisons of the specified models. They do not establish that a random intercept adequately models each scientific study. In particular, we do not reproduce the random-slope sleepstudy example or a worker-by-machine interaction. All fits are marginal maximum likelihood, not REML.

The runner checks every row, not a sample: population and conditional fitted values, both residual definitions, all group effects, coefficients, covariance, standard errors, normal Wald tests/intervals, variance components, ICC, likelihood and AIC. Group labels, ordering, retained rows and observation counts are exact. Both R packages supply independent model estimates. statsmodels supplies its own ML estimates; its fixed-effect covariance is recomputed as plug-in GLS to match lme4 and our contract. All Python mixed fits must converge; warnings are retained. Both R references use vcov() and explicit normal Wald calculations to match our declared inference. Default nlme t-tests and profile-likelihood intervals use different conventions.

Look closely at numerical differences

The graph shows the difference between native and lme4 conditional fitted values, scaled by a million to make rounding differences visible. Zero means exact agreement. Every point is a retained observation; panel units differ by dataset. It is a numerical agreement plot, not a model residual diagnostic.

Default public-data tolerances are 1e-7 absolute plus 1e-6 relative. The four observation-length output vectors use 1e-6 absolute in their outcome’s units, plus 1e-6 relative, so residuals close to zero are not tested by relative error alone. Likelihood and AIC use 1e-7 absolute plus 1e-10 relative. Original synthetic fixtures retain their uniform 1e-7 + 1e-6 × abs(reference) tolerance. These policies are recorded with each source fixture and live report. An additional native-versus-statsmodels check keeps the stricter original uniform tolerance for all quantities; reference-optimizer rounding allowances cannot hide divergence between those two estimates.

The High School and Beyond sample illustrates an optimizer precision limit: lme4 and nlme have effectively identical likelihoods but slightly different variance estimates. Conditional residual differences can reach a few 1e-7 when the residual itself is nearly zero. The profile scores below independently check stationarity at each estimate; they are derivatives of negative profile log-likelihood with respect to log(1 + tau²/sigma²). Zero is the interior optimum condition. Raw scores depend on dataset size and curvature and should not be compared across different studies as a universal error metric.

Reproduce without fetching data

The CSVs and lme4/nlme expected outputs are checked into the repository. cargo test --workspace and tests/lmm.php check the published fixtures without R, Python or network access. The live comparison requires lme4, nlme and the pinned Python environment, but not mlmRev: it reads the saved Hsb82 CSV.

cargo test --workspace --locked
PHP=/opt/homebrew/bin/php STATS_EXTENSION="$PWD/target/release/libphp_stats.dylib" \
  .context/notebooks-venv/bin/python docs/verifications/compare_lmm.py --public
QUARTO_PYTHON="$PWD/.context/notebooks-venv/bin/python" PHP=/opt/homebrew/bin/php \
  quarto render docs/notebooks/lmm-public-verification.qmd

Use matching PHP headers to build the extension first; use .so on Linux. The saved live report records full outputs, source checksums, runtime versions, the extension hash, warnings, tolerances and score/error checks. Re-execute this page after statistical-code or source-data changes; merely rendering saved outputs is not new verification.

This strengthens evidence for the current Gaussian random-intercept ML model. It does not establish correctness for random slopes, REML, other response families, assumption checks, or finite-sample group-level inference.
