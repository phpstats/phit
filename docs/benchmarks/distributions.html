Distribution performance

This benchmark times distribution and descriptive functions in five ways on identical inputs: a PHP loop of scalar calls, one PHP batch call, an internal Rust loop, vectorized R, and SciPy. Raw results keep every measurement, numerical summary, input hash, runtime version, thread setting, and peak RSS.

Numerical comparisons before timings

All input cases are verified across implementations before any timing phase begins. Seventeen evenly spaced output values plus min/max use the distribution fixture tolerance: 1e-300 + 1e-12*abs(reference), or 1e-15 + 1e-12*abs(reference) for quantiles. Sum and sum-of-squares consume all outputs, with tolerance 1e-9 + 1e-10*abs(reference) to allow different accumulation orders. Mean/variance outputs are checked directly. R is the benchmark reference; the separate R/SciPy/mpmath record adjudicates reference differences and tests extreme/boundary values more broadly.

phit’s comparisons must pass. SciPy discrepancies are recorded and labeled without relaxing phit’s tolerance. Every timed output summary is checked again. Individual elements of the large vectors are not all compared; the aggregates and sampled values complement the small reference suite.

Timing boundaries and interpretation

Distribution calls allocate and populate the complete output vector. The PHP scalar loop constructs a distribution and crosses the PHP/native boundary for each value; batch calls construct it once and stream values natively. The internal Rust loop uses the same validation and an allocated result vector. Descriptive mean/variance has one PHP native call; there is no invented scalar-loop equivalent for those operations.

JSON I/O, startup and output summaries are outside timed calls. PHP input/output conversion and native validation are included. R/SciPy start with native numeric vectors. Runtime reclamation/garbage collection of prior results contributes to the observed API cost. Peak RSS is the whole worker process, including imports, JSON parsing, inputs, outputs and summaries, not isolated kernel memory. Process elapsed time and input loading time are recorded separately.

R’s timer has millisecond resolution. Small distribution cases batch 100 calls; mean/variance batch enough calls to process at least ten million input values per measurement, with a minimum of ten calls. Per-call times divide by the batch count. All raw timings must be positive. The thread settings do not make different numerical implementations equivalent. PHP scalar and batch worker order alternates by case. Machine load, timer precision, and garbage collection affect the measurements, which describe these workloads only.

Reproduction

python3 -m venv .context/distributions-venv
.context/distributions-venv/bin/pip install -r tests/benchmarks/distribution-requirements.txt
# R with jsonlite is a development-only reference dependency.
cargo build -p phit --release --locked
cargo build -p stats-core --release --locked --example distribution_bench
PHP=/path/to/matching/php .context/distributions-venv/bin/python tests/benchmarks/run-distributions.py
python3 scripts/distribution-docs.py

The runner accepts --sizes, --operations, --repeats, --output and --resume. A partial report is marked complete: false; resume requires matching binary hashes, seed, repetitions, thread settings and input hashes. It keeps completed verification/timings and recomputes any changed input. Use a new output file for a different build. Fixed seed 20261012 and saved NumPy/Python versions specify input generation; SHA-256 records the exact JSON values actually used.
