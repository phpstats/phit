Building and maintaining the documentation

Edit the Quarto .qmd sources in docs/, render them, and commit the rendered HTML with its sources. The statistical engine does not depend on Quarto, and the root README.md stays a short repository entry point.

Path Role
docs/*.qmd, docs/**/*.qmd Editable sources, including the executable walkthroughs
docs/_quarto.yml Site configuration and sidebar navigation
docs/_freeze/ Saved results of executed code; kept in version control
docs/_site/ Quarto’s build output; gitignored
docs/*.html, docs/site_libs/ Rendered site, copied from _site/ by scripts/render-docs; committed
.quarto/ Quarto’s local state; gitignored

Render and preview

Install the Quarto CLI (on macOS, brew install --cask quarto). The site is currently rendered with Quarto 1.10.18.

quarto preview docs
./scripts/render-docs

./scripts/render-docs runs quarto render docs and copies the result from docs/_site/ into docs/. quarto render docs alone writes only docs/_site/.

  • A full render reuses the saved results in docs/_freeze/, so it needs no Python, R, or built extension.
  • A render that reuses saved results checks presentation only. It is not a new numerical verification, and the walkthroughs show the versions from their last execution.
  • Rendering a single page executes its code, even when a full render would reuse the saved results. Quarto’s freeze documentation explains why. Any edit to a computational walkthrough, including a prose edit, needs a single-page render to update its frozen content.
  • A single-page render can remove docs/site_libs/ files that other pages still use. Finish with ./scripts/render-docs, or restore docs/site_libs/ from git.

Recompute the walkthroughs

Follow the development setup to select a matching PHP, and install R with Rscript on the PATH. The mixed-model references need R’s lme4, and the published-data comparison also needs nlme. These are development dependencies only.

Rscript -e 'install.packages(c("lme4", "nlme"),
  repos = "https://cloud.r-project.org")'

python3 -m venv .context/notebooks-venv
.context/notebooks-venv/bin/pip install -r docs/notebooks/requirements.txt
export QUARTO_PYTHON="$PWD/.context/notebooks-venv/bin/python"
# macOS; on Linux use libphit.so and the matching PHP paths.
export PHP=/opt/homebrew/bin/php
export PHP_CONFIG=/opt/homebrew/bin/php-config
cargo build -p phit --release --locked
export STATS_EXTENSION="$PWD/target/release/libphit.dylib"

Then run every comparison and render the walkthroughs:

PY=.context/notebooks-venv/bin/python
PHP=$(command -v php) $PY docs/verifications/run_all.py
for f in docs/notebooks/*-math.qmd docs/data/lmm/index.qmd; do
    quarto render "$f"
done
python3 scripts/site-export.py
./scripts/render-docs

run_all.py writes every docs/verifications/*-results.json, the test-suite record, and the run’s environment. scripts/site-export.py turns them, and the benchmark results, into the evidence records under site/.

  • Single-page renders execute every chunk in order and update _freeze/. The final step assembles the site.
  • RSCRIPT selects a non-default Rscript. QUARTO_PYTHON selects the virtual environment without putting machine-specific paths in the project configuration.
  • A change to input data or an estimator requires re-execution even if the prose is unchanged.
  • Review the .qmd, _freeze/, and comparison-report diffs together. The outputs record evidence from the environment used, not a guarantee for every platform.
  • The comparison scripts capture PHP warnings to keep their JSON valid, then show and check those warnings explicitly.

Writing a walkthrough

Each implemented estimator has a derivation walkthrough and an equivalent-model verification, following the notebook guide. Do not create placeholder notebooks for methods phit does not implement.

  • Use a small, reproducible simulated dataset with named variables, units, noise, and meaningful relationships. State its generating equation, seed, population parameters, and observed correlations. Save and share the observations, and label them synthetic. See the learning-data convention.
  • State the model’s assumptions and input ordering, derive the calculations before showing them, connect result fields to the production code, and explain edge cases.
  • Give equivalent R, statsmodels, and PHP calls where those references support the estimator. State differences in statistical conventions rather than silently adjusting one library’s results.
  • Keep assertions near the results and keep executed outputs. Share inputs with the reference tests where possible.

Authoring rules

  • Ordinary fenced blocks (python, r, php) are displayed only. {python} chunks execute in the Jupyter kernel; the comparison runners invoke R and PHP from Python.
  • Execution starts in docs/, and the code finds the repository root by locating Cargo.toml. A missing dependency or failed assertion must fail the render.
  • Use relative links to .qmd pages so Quarto rewrites them to HTML.
  • Keep local reference data and scripts next to the verification page.
  • Use a Quarto-aware editor. Generated .ipynb files are not maintained sources.

For a prose-only page, render the site and check navigation and local links. For a computational change, rerun the affected pages and comparison scripts, inspect the output, and run the Rust and PHP checks.

Example pages with charts

An example page with a chart includes _generated/{name}.md, which scripts/docs-examples.php writes from docs/examples/scripts/{name}.php.

  • The script runs in an empty directory beside this checkout’s vendor/, with the CSV files it names copied from docs/data.
  • The generated file holds the script without its opening tag and Composer bootstrap, its output, and its phiz chart. The downloadable script keeps the bootstrap.
  • phiz is a Composer dev dependency for this purpose only. The scripts also need the phit and phpolars extensions.
composer install
php -d extension=target/release/libphit.dylib \
    -d extension=/path/to/libphp_polars.dylib \
    scripts/docs-examples.php

Commit the generated files. Rendering the docs does not run the scripts.

Figures

Benchmark and notebook figures use the shared R and ggplot2 renderer described in Figure conventions. Python computes and verifies, and does not draw; Matplotlib is not a documentation dependency.

To refresh saved figures without estimating or timing anything:

Rscript docs/figures/render.R --all
./scripts/render-docs

The renderer reads saved reports and small point snapshots exported by the notebooks. Executing a single .qmd page calls the renderer when needed.

Publishing

phpstats.org imports the rendered HTML committed under docs/, and GitHub Pages serves the same directory at https://phpstats.github.io/phit/. Neither runs Quarto.

  • Every page in the docs/_quarto.yml sidebar needs its rendered HTML committed.
  • After editing sources or refreshing frozen results, run ./scripts/render-docs and commit the HTML and assets with their sources.
  • docs/.nojekyll lets GitHub Pages serve directories whose names start with an underscore.
